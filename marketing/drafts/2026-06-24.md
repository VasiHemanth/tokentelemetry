### Draft

**Title:** I built a free local dashboard that shows what your Ollama sessions actually cost (electricity, not pretend API rates)

**Body:**

If you run Ollama or llama.cpp for coding agents you've probably noticed most "cost" dashboards either skip local models entirely or price them at OpenAI API rates, which is meaningless.

I built [TokenTelemetry](https://github.com/VasiHemanth/tokentelemetry) to fix that for my own setup and opened it up. Here's what it actually does for local models:

**Pricing by electricity, not tokens**
Set your machine's watts-under-load and kWh rate, and it estimates the electricity cost per session. It auto-detects your chip (M-series, etc.) for a starting watt figure, but you can measure or override. A 4B model isn't costed the same as a 70B — throughput scales the estimate.

**Live process monitor (just shipped)**
New System panel shows real-time disk IO, CPU, and memory for every AI agent process running on your machine — including Ollama and llama.cpp processes. Write rates above 5 MB/s trigger a warning. (This was motivated by the Codex Desktop disk-write incident — figured local model runners deserve the same watch.)

**Sessions from Ollama, llama.cpp, vLLM all tracked**
Detected by endpoint/provider, so a local model with the same name as a cloud model never accidentally picks up cloud pricing.

**Zero config, 100% local**
No SDK, no cloud, no code changes. It reads the log files your agents already write. `npx tokentelemetry` and you're in.

Source: https://github.com/VasiHemanth/tokentelemetry

Happy to answer questions about the power estimation approach — there are some interesting edge cases when models share hardware with other workloads.

## Dev.to — Weekly Article

**Title:** How to see what your AI coding agents are actually doing (and what it costs)

**Target audience:** developers using Claude Code, Codex, Cursor, or local models who track costs manually or not at all

**Outline:**

### 1. The problem: agents cost money in ways that don't add up
- You run Claude Code, maybe Codex on the side, maybe an Ollama model for quick tasks
- Your billing dashboard shows a monthly total — not per-session, not per-project, not per-agent
- When you run agents in parallel the combined burn rate is invisible
- When a parent agent spawns subagents, only the parent's tokens show up

### 2. What "full visibility" actually looks like
- Per-session cost with model, token breakdown (input/cache/output), and duration
- Subagent delegation — which spawned what, at what cost, on which model
- Concurrency timeline — which sessions overlapped and the combined $/hr during those windows
- Workflow grouping — total cost for a named task across all agents

### 3. Local models deserve real cost tracking too
- Cloud pricing applied to Ollama sessions is meaningless
- Real cost = electricity: watts × session duration × kWh rate
- TokenTelemetry auto-detects your chip, you set or measure actual draw
- New: live process monitor — CPU, memory, disk IO per running agent process

### 4. Zero-config setup (the part I actually care about)
- No SDK to install, no code to change, no cloud account
- It reads logs agents already write
- `npx tokentelemetry` → dashboard opens → your sessions appear
- Supports 35+ agents: Claude Code, Codex, Cursor, Copilot, Grok Build, Gemini CLI, Antigravity, Ollama, local vLLM/llama.cpp setups, and more

### 5. This week's additions (a real-world use case)
- Ran 3 agents in parallel on a refactor — concurrency timeline showed the combined burn peaked at ~$1.20/hr for about 40 minutes
- Tagged all related sessions as a "auth-refactor" workflow: total $0.83, 4 agents, 2h 14m — finally a number I can use for estimating future work
