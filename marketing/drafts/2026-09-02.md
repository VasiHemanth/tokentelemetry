### Draft post

**Title:** I built an open-source, fully local dashboard to track what my AI coding agents cost — no cloud, no telemetry sent anywhere

**Body:**

I use a handful of AI coding agents daily (Claude Code, Codex, Gemini CLI, a local Ollama setup) and wanted one place to see what they all cost without sending my data anywhere.

So I built TokenTelemetry — it reads the session logs these agents already write to disk and gives you a local dashboard with per-session cost breakdowns, tool-call traces, and per-model analytics. No SDK to add, no code changes, no account to create. Install is one line (`curl | bash`) and it runs on localhost.

A few things the selfhosted crowd might find interesting:

- **Fully local.** All data stays on your machine. The one optional outbound call (update check) has a toggle to turn it off, or set `TT_NO_UPDATE_CHECK=1`.
- **Remote access if you want it.** Run with `--host 0.0.0.0` and it generates an access token printed to your console. There's a QR code in Settings so you can scan from your phone on the same network. Works well on a Tailscale tailnet.
- **Custom data directory.** `--data-dir /your/path` moves all state to wherever you want — handy if your system drive is small.
- **Local models priced by electricity.** If you run Ollama/llama.cpp/vLLM, sessions are costed by your actual hardware power draw and kWh rate instead of making up API prices.
- **Anonymous telemetry is opt-out.** One click in Settings, or `DO_NOT_TRACK=1`. It sends no code, prompts, file paths, or costs — just feature-usage signals. But you can turn it off completely.

Supports 35+ agents. MIT licensed. Python + Node, works on macOS, Linux, and Windows.

GitHub: github.com/VasiHemanth/tokentelemetry

Happy to answer questions about the architecture or what it tracks.

**Target audience:** Developers who self-host AI tools (Ollama, vLLM, llama.cpp) alongside cloud agents and want to understand their real costs.

### Outline

1. **The problem** (150 words)
   - You run 3-4 agents. Some are cloud API (Claude Code, Codex), some are local (Ollama). You have no idea what any of it actually costs in total. Cloud agents bill per token but the dashboard is scattered. Local agents feel "free" but electricity isn't.

2. **What "cost" means for local models** (200 words)
   - API pricing doesn't apply. The real cost is watts × time × kWh rate.
   - TokenTelemetry detects your chip (Apple Silicon, NVIDIA via nvidia-smi) and estimates watt-hours per session.
   - You can set your own power draw and electricity rate, or use the Measure button on supported hardware.
   - Also tracks CO₂ based on your grid's carbon intensity.

3. **Comparing local vs cloud on the same task** (200 words)
   - TokenTelemetry shows "cloud savings" — what a local session would have cost at a reference cloud model's API rates.
   - Model efficiency table: compare local models by tokens/sec, Wh per 1M output tokens.
   - Real example: a local 7B model at 45 tok/s vs Claude Sonnet for a similar task — show the cost difference.

4. **One dashboard for everything** (150 words)
   - 35+ agents tracked without any config. It reads the logs they already write.
   - Per-session traces, per-project budgets, subagent cost breakdowns.
   - Runs on localhost. Optional remote access for headless setups (Tailscale-friendly, token-gated).

5. **Getting started** (100 words)
   - One-line install. `npx tokentelemetry` or `curl | bash`.
   - Point Settings → Local power at your hardware. Set your kWh rate.
   - Open the dashboard. Everything's already there.
