## LinkedIn — Cost-visibility post (longer version of X insight)

> **When an AI coding agent runs up a big token bill, can you tell which step caused it?**
>
> Most cost tooling stops at the session total: this run cost X. Useful for a bill, useless for fixing anything — because the expense is almost never spread evenly. It's usually one or two steps: a tool call that pulled in a huge file, a retry loop, a reasoning step that ran long.
>
> TokenTelemetry now shows the tokens each step of a trace used — a count on every step and in the step index — so you can open an expensive session and immediately see *which* call was the offender, instead of scrolling and guessing.
>
> That's the difference between knowing a session was costly and knowing what to change. And it pairs with intent capture (what the agent was actually trying to do on a run), so a trace tells you both the goal and where the tokens went.
>
> All read locally from logs already on your disk. No SDK, no cloud account, no code changes.
>
> → github.com/VasiHemanth/tokentelemetry
