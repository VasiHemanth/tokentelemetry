## Reddit — r/LocalLLaMA value post

**Rotation:** ClaudeAI → ChatGPTCoding → **LocalLLaMA** (this week) → selfhosted. Monday's comments in this sub warm it up.

**Title:** I finally measured what my local coding models cost to run — in watt-hours, not vibes

**Body:**

Everyone says "just run it locally, it's free." It's not free — it's electricity — and I realized I had no idea what the number actually was. So I made my dashboard measure it, and figured this crowd would care about the method more than the marketing.

What it now tracks per local session, all read off my own machine:

- **Throughput** — real tok/s from wall-clock generation time, not a spec-sheet number. A 7B and a 32B are wildly different here.
- **Energy** — watt-hours, from my chip's actual power draw under load × generation time (auto-detected wattage on Apple silicon; asks you to enter/measure draw where it can't detect).
- **Electricity cost** — Wh × your kWh rate. Mine works out to roughly [$0.00X] for [a typical session] — small, but not zero, and it adds up across a day of agent runs.
- **Savings vs cloud** — same tokens re-priced at a reference cloud model (default Sonnet) so you can see what you're *not* paying an API for.
- **CO₂** — Wh × your grid's carbon intensity, if you set it.

The part I find most useful is a **model-efficiency table**: local models ranked by tok/s and **Wh per 1M output tokens**. It reframes the "which local model" question — the fastest model isn't always the most energy-efficient per token, and now I can see the tradeoff instead of guessing.

It works by probing loopback Ollama for installed/loaded models (plus `nvidia-smi` for GPU stats if you have one) — no remote host exposed, macOS/Linux/Windows. It's 100% local and open source: [TokenTelemetry](https://github.com/VasiHemanth/tokentelemetry). It passively reads the logs/endpoints your tools already produce — no SDK, no cloud, no code changes; `npx tokentelemetry` and you're looking at your own numbers in about 30 seconds.

Genuinely curious what tok/s and Wh/1M-token numbers other people are seeing on their local setups — drop yours and I'll compare against mine.

## Dev.to — weekly article (outline)

**Title:** Local LLMs aren't free — here's how to measure what they actually cost, in watt-hours

**Target audience:** developers running Ollama / llama.cpp coding models who assume local = zero cost and have never seen a power number

**Outline:**

### 1. "Free" is the wrong mental model
- Local removes the *API bill*, not the cost — you're paying in electricity (and hardware, and heat)
- Why "it's free" quietly stops you from optimizing: you can't improve a number you never measure

### 2. Throughput: measure it, don't quote the spec sheet
- Real tok/s from wall-clock generation time per session, not a benchmark you saw once
- Why a 7B vs 32B gap matters more than people expect for iterative agent work

### 3. Turning tok/s into watt-hours
- The formula: watts-under-load × generation time → Wh; auto-detected chip wattage (Apple silicon) with an honest "enter/measure your draw" fallback
- Wh × kWh rate = electricity cost; Wh × grid carbon intensity = CO₂
- Keep it honest: label estimates as estimates, show where each number comes from

### 4. The metric that actually changes decisions: Wh per 1M tokens
- Fastest ≠ most efficient — rank local models by energy per token, not just speed
- Savings vs a cloud reference model: what you're *not* paying an API, priced apples-to-apples

### 5. Doing it without a benchmark harness
- Probe loopback Ollama for installed/loaded models (+ `nvidia-smi` for GPU); no remote host exposed
- `npx tokentelemetry`, reads what your tools already expose, 100% local, ~30 seconds
- Walk-through: Local Models page → efficiency table → open a session's energy card → [your own real numbers]

**Closing CTA:** GitHub link + "what's your tok/s and Wh/1M tokens? post your local setup, genuinely comparing"
