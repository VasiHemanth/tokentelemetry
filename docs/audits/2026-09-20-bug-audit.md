## Confirmed Findings

All 8 findings were initially flagged high by scanners/deep auditors and downgraded to medium by verifiers after adversarial testing.

### M1 — ZCode HWM cached tokens understates cost ~2.8x on cache-heavy sessions

**File:** `backend/main.py:5814`  
**Verifier:** CONFIRMED high-confidence, downgraded to medium

`tokens["cached"] = max(tokens["cached"], cache_read)` accumulates the per-turn high-water-mark instead of a cumulative sum. `calculate_cost` prices only the HWM value. The canonical fix (`_cached_sum += cache_read` paired with separate `tokens["cached"] = max(...)` for display) was applied to the Claude scanner at lines 6671-6672/6678 but not to ZCode. Repro: 10 identical turns with `cache_read=10000` yields `cached=10000` (HWM) vs correct `100000` (cumulative); ~2.8x total-cost understatement in cache-heavy sessions. Same defect exists in OpenCode at line 8881. `history_store.py:238` falls back to `cached` when `_cached_sum` is absent, so analytics `cache_reads` for ZCode/OpenCode is also understated.

### M2 — ZCode scan loop has no per-session guard; one bad row drops all remaining sessions

**File:** `backend/main.py:5730`  
**Verifier:** CONFIRMED high-confidence, downgraded to medium

One `try/except` wraps the entire per-DB body including the `for srow in rows:` loop. An out-of-range epoch value (`datetime.fromtimestamp` raises `ValueError` for ns-scale integers — reproduced), a `sqlite3.OperationalError` from a locked DB during a per-session query, or any row-specific error drops all subsequent sessions with only a DEBUG log. Kimi does this correctly (per-session `try/except ... continue`). Fix: mirror the Kimi pattern.

### M3 — Kimi `config.toml` parse failure silently prices all sessions at $0.00

**File:** `backend/main.py:4964`  
**Verifier:** CONFIRMED high-confidence, downgraded to medium

`_kimi_default_model()` wraps `tomllib.load` in a bare `except Exception: return "kimi-for-coding"`. `pricing_data.json` defines `kimi-for-coding` at `{in: 0.0, out: 0.0, cached_read: 0.0}`. A TOML syntax error or permission error during any scan reprices every Kimi session at $0.00; no `stub` is set, so `upsert_sessions` takes the full `DO UPDATE SET` branch and overwrites `model` and `cost` for all persisted rows. Self-healing once the config is repaired, but permanent if Kimi prunes session dirs first. Reproduced with real module.

### M4 — Muse/DSH `delegated_cost` nested inside `sess["delegation"]`, invisible to all analytics totals

**File:** `backend/main.py:12069`  
**Verifier:** CONFIRMED high-confidence, downgraded to medium

`_scan_muse_sessions` and `_scan_dsh_sessions` set `sess["delegation"]["delegated_cost"]` but never set the top-level `sess["delegated_cost"]` that `get_analytics` reads at line 12069 (`dcost = s.get("delegated_cost") or 0.0`). Result: by_agent/by_day/total all show $0 for Muse/DSH delegation spend. The UI is self-inconsistent: the Delegation KPI pair shows non-zero tokens at $0.00 while the subagent-type table one card below shows the real cost. `history_store.py:244` also persists 0.0. Reproduced with synthetic session.

### M5 — Stub row pinned at first-partial-parse values with no update path

**File:** `backend/history_store.py:258`  
**Verifier:** CONFIRMED high-confidence, downgraded to medium

The stub conflict clause updates only `last_seen_at` and `source_present`. A Codex session where `_partial_parse=True` on every scan inserts with first-sighting partial token counts (e.g. 50k/$0.40) and those values never change — the stub branch has no notion of "stub vs older stub." The analytics merge at `main.py:12049` then prefers the stale stored row over the live stub. Self-heals when the parse eventually succeeds (full update branch). Reproduced by calling `upsert_sessions` twice with `stub=True` then confirming stored values are frozen.

### M6 — OpenCode first-DB-wins dedup overwrites better data with stale channel copy

**File:** `backend/main.py:8798`  
**Verifier:** CONFIRMED high-confidence, downgraded to medium

`_opencode_dbs()` returns `[OPENCODE_DB, *sorted(others)]` (canonical first). Dedup at line 8798 is strictly first-DB-wins with no recency or token-count comparison. A session id present in both the canonical and a newer channel DB (after copying a data dir) uses the stale canonical copy; no `stub` key is set; full DO UPDATE SET re-writes smaller stale values every scan. Trigger requires a copied data dir (not the common channel-switch path), but impact is persistent once triggered. Reproduced with synthetic two-DB setup.

### M7 — Budget evaluation omits `delegated_cost`; alerts can fail to fire for delegation-heavy users

**File:** `backend/main.py:11767`  
**Verifier:** CONFIRMED high-confidence, downgraded to medium

`_compute_budget_status` reads only `s.get("cost")`, never `delegated_cost`. For a Claude session with parent cost $2 and delegated cost $8 against a $10 budget: budget shows 20% used, no alert fires; analytics shows 100%. Affects token budgets too (`tokens["total"]` excludes `delegated_*` fields). Reproduced with real module. Downgraded from high because budgets are observational (no spend blocking) and analytics still reports the true figure.

### M8 — `delegated_cost` permanently zeroed when subagent files are deleted and parent receives new messages

**File:** `backend/history_store.py:284`  
**Verifier:** CONFIRMED high-confidence, downgraded to medium

When subagent files under `~/.claude/projects/<enc>/<sid>/subagents/` are deleted and the user later writes to the parent session, the cache misses (new parent mtime), `_claude_subagent_usage()` returns `None`, `delegated_cost` is never set on the session dict, and `upsert_sessions` writes `delegated_cost=0.0` with no "keep existing if new is zero" guard. No recovery path. Reproduced by calling upsert with then without delegation keys. Requires file deletion plus continued activity in the same session; impact is permanent for affected sessions.

## Refuted Candidates

**H4 — Kimi zero-token session clobbers durable rows:** REFUTED. Mid-parse exceptions hit the outer `try/except ... continue` and drop the session entirely rather than emitting a zero-token row. Zero-token emissions only occur for garbage wire.jsonl files that never had real stored rows to overwrite. The Codex #350 shape requires `_read_ok=True` before the exception, which Kimi's structure prevents.

**H10 — `scan_cache >= mtime` freezes sessions forever:** REFUTED. `>=` is self-healing: any subsequent write to the parent transcript produces a new mtime strictly greater than the cached `_mtime`, causing a miss and full re-parse. Persistent freeze requires mtime going backwards AND the session never being written to again — exotic. PR #374's `==` change is defensive hardening, not a bug fix.
