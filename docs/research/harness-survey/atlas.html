Top 12 finds

Ranked by user value × extraction cost. Every one is a single file or a single SQL query.

01 · Copilot CLI

Ground-truth token & billing table

~/.copilot/session-store.db → assistant_usage_events

Every token class split out, plus total_nano_aiu and request_multiplier — Copilot's premium-request billing units, which TT cannot currently compute. Also carries time_to_first_token_ms and inter_token_latency_ms, giving real tok/s for the power model. Replaces the cache-token heuristic with recorded truth.

02 · Codex

Scheduled automations

~/.codex/automations/<id>/automation.toml

RFC-5545 rrule, kind of cron or heartbeat, status, model, reasoning effort, target repo, plus an accumulating memory.md per automation. Two live here. This is the "Codex stores schedules" hypothesis, confirmed and trivially parseable.

03 · Claude Code

Subscription rate-limit state

~/.claude.json → cachedUsageUtilization

Five-hour and seven-day utilisation percentages with reset timestamps and remaining dollars, cached on disk. The single clearest answer to "how close am I to my limit," and it needs one key read.

04 · Claude Code

Background job fleet

~/.claude/jobs/<id>/state.json + daemon/roster.json

48 jobs with a real state machine (done/blocked/working/stopped), token counts, fan-out task lists, and linked PR/issue children. Cross-reference daemon/roster.json and sessions/<pid>.json for what is alive right now.

05 · Cursor

AI-authored code percentage

~/.cursor/ai-tracking/ai-code-tracking.db → scored_commits

Per-commit line counts split into tab-completion, composer, and human, resolving to v2AiPercentage. Directly answers "how much of this repo did the agent write" — a headline metric no other harness offers.

06 · Hermes

Recorded cost, estimated and actual

~/.hermes/state.db → session_model_usage

Per session and model: five token classes, billing_provider, billing_mode, and both estimated_cost_usd and actual_cost_usd with a cost_source. An independent oracle to validate TT's own cost math against. Verified unread by main.py.

07 · Antigravity

Conversation index without protobuf

antigravity-cli/conversation_summaries.db

131 rows carrying title, step_count, status, agent_name, workspace, killed, nesting_depth and parent_conversation_id. Also battle_id and winning_conversation_id — Antigravity runs competing attempts and records the winner.

08 · Grok

Credit balance, already in a parsed file

~/.grok/logs/unified.jsonl → "billing: fetched credits config"

creditUsagePercent, subscriptionTier, and billing-period bounds sit in rows of a log TT already opens for token aggregation. A new message-type filter, no new file read.

09 · Codex

Thread registry and spawn graph

~/.codex/state_5.sqlite

threads gives tokens, model, reasoning effort, git branch/sha, sandbox policy and approval mode per session. thread_spawn_edges has 60 parent→child rows, giving Codex delegation parity with Claude for one query.

10 · VS Code

Agent permission and auto-merge config

Code/User/globalStorage/agent-host-config.json

Tool allow/deny lists plus agentMerge.* — whether VS Code will fix CI, resolve conflicts, and merge a PR on its own. High-consequence settings a user should be able to see in one place.

11 · LM Studio

Parsed GGUF headers, free

~/.lmstudio/.internal/gguf-metadata-cache.json

contextLength, parameters, numLayers, attention head counts — already parsed and cached by path. Ollama's manifests do not carry context length at all, so this is the cheapest route to a complete local-model inventory.

12 · Prime Agent

Live Python kernel state

~/.prime/agent/session-artifacts/<id>/kernel-state.json

savedNames lists the variables persisted across turns in the agent's sandbox. No other harness has an execution-state checkpoint. "N variables carried across M turns" is a differentiator panel nothing else can render.

Security posture panel

This install runs approval_policy = "never" and sandbox_mode = "danger-full-access", with 15+ [projects."<path>"] trust_level = "trusted" entries. Nothing else on the machine surfaces an agent's blast radius this plainly, and it is a genuinely useful thing to show a user.

Gotchas
  • All SQLite is sqlx-managed with live -wal/-shm. Open read-only; the Electron app holds them.
  • ~/.codex/sqlite/*dev.db are development duplicates. Skip them or you double-count.
  • Sessions are date-partitioned YYYY/MM/DD, not flat.
  • Timestamp columns mix seconds and _ms. Check per column.
  • transcription-history.jsonl and dictation-history/ hold raw voice transcripts. Count only.

Cheapest win on the whole machine

unified.jsonl is already opened and parsed by _grok_usage_from_unified_log, which filters for a single message type. Adding one more filter for "billing: fetched credits config" yields creditUsagePercent, subscriptionTier, and the weekly period bounds — a full quota gauge with no new file access.

Gotchas
  • GROK_HOME relocates the entire root; GROK_CONFIG_PATH overrides config without touching the file.
  • rewind_points.jsonl embeds full file contents. Surface counts and paths only, never content.

  • Session dirs are URL-encoded cwds (%2FUsers%2F…). Globs need quoting and percent-decoding.
  • .lock siblings sit next to nearly every mutable JSON. Skip them when globbing.

Context length is not in the manifest tree

For GGUF models it must come from either the server log's global OLLAMA_CONTEXT_LENGTH / runtime default_num_ctx (neither is per-model), or from parsing the GGUF header — the magic, version, tensor count and KV count are the first 24 bytes of the blob, with the <arch>.context_length KV immediately after. A bounded few-KB read of one blob is enough. LM Studio already does exactly this, which proves it practical.

  • Manifest sizes summed give 159.8 GB vs du's 149 GB — shared layers are deduplicated on disk but counted once per manifest.
  • Logs rotate on app restart, keeping 6 generations. That was ~15 days here; a long-running daemon may have one file spanning months. Never assume a window.
  • OLLAMA_MODELS relocates the whole models dir.
  • The Gin access line carries path, status and latency but not the model name — correlating a /api/chat call to a model needs the nearest preceding /api/show.

Handling rules

Applied throughout this survey; they should carry into any scanner built from it.

  • Never read credential values. auth.json (codex, grok, pi, prime, hermes, opencode), oauth_creds.json + google_accounts.json (gemini, qwen), .credentials.json (claude), cursorAuth/* in Cursor's ItemTable, ~/.ollama/id_ed25519, ~/.vibe/.env, ~/.mcp-auth/**, users.password_hash (omnigent), connectionToken (VS Code), ide/*.lock authTokens (qwen). Existence and key names only.
  • Never surface raw prompt or file content. rewind_points.jsonl embeds whole files; agentKv:blob:* is raw model I/O; .tempmediaStorage/dom_*.txt is full page DOM; transcription-history.jsonl and dictation-history/ are voice transcripts; prompts/prompt_N.txt, vibehistory, ~/.ollama/history, paste-cache/ and last-copy.txt are raw user text. Counts, paths and timestamps only.
  • Secrets are not always in a file named like one. ~/.vibe/.env sits at the harness root, and Cursor keeps live tokens in the same key-value table as ordinary UI state. A filename heuristic misses both.
  • Read SQLite read-only. Codex, Cursor, VS Code, LM Studio and Hermes all hold live WAL locks.
  • Filter FTS5 shadow tables (*_data, *_idx, *_content, *_docsize, *_config) or table counts inflate across Copilot, Omnigent, Hermes and Grok.
  • Honour relocation env vars: GROK_HOME, HERMES_HOME, OLLAMA_MODELS, HF_HOME, XDG_DATA_HOME, TT_CLINE_DIR.
  • Do not double-count the shared skill pack. The same Cloudflare marketplace skills are byte-identical under .grok, .qwen, .vibe, .openclaw, .pi, .copilot and .claude.
